# 从零开始，一步步跑出压测数字（零基础版）

> 目标：跑完这个手册，你能拿到两个数字——**同步版的 P99** 和 **异步版的 P99**，填进简历。
> 全程大约 30 分钟（不含装 Docker 的时间）。

---

## 第 0 步：先自查三件事（3 条命令）

打开终端：**在文件夹 E:\my-project\offermate 里，按住 Shift + 右键 → 在此处打开 PowerShell 窗口**。

然后依次输入下面三条，各按回车：

    docker --version
    java -version
    docker compose version

对照结果：

| 看到什么 | 说明 |
| --- | --- |
| docker 版本号 + java 21 + compose 版本号 | ✅ 太好了，直接跳到第 1 步 |
| docker 那行报「不是内部或外部命令」 | ❌ **Docker 没装**，先看文件末尾的「没有 Docker 怎么办」 |
| java 不是 21 | ❌ 需要 JDK 21（压测工具用了虚拟线程） |

---

## 第 1 步：把中间件起起来（MySQL / Redis / RocketMQ / MinIO）

在同一个终端里：

    cd E:\my-project\offermate
    docker compose up -d

**第一次会下载镜像，需要几分钟**（网络慢的话更久）。

起完之后检查：

    docker ps

你应该看到 5 个容器（mysql、redis、rocketmq-namesrv、rocketmq-broker、rocketmq-dashboard）状态都是 Up。

> MinIO 在 docker-compose.yml 里挂了 `profiles: ["minio"]`（官方镜像已下架，默认不启动），要演示上传/秒传再执行一次 `docker compose --profile minio up -d`，那时才看到第 6 个容器。

⚠️ **如果容器起来又退出**：多半是内存不够。先关掉浏览器、IDEA、微信等程序，再执行 docker compose restart。

---

## 第 2 步：确认数据库表建好了

数据库的建表语句已经挂在 Docker 的自动执行目录里了，**第一次启动 MySQL 时会自动执行**。

验证一下（把下面整行粘进去回车）：

    docker exec -it offermate-mysql mysql -uroot -proot123456 -e "use offermate; show tables;"

看到 9 张表（sys_user、job、resume_file、resume、application、notification、mq_consume_log、ai_chat_log、rate_limit_config）就对了。

如果提示数据库不存在或者没有表，手动执行一次：

    type server\src\main\resources\db\schema.sql | docker exec -i offermate-mysql mysql -uroot -proot123456

---

## 第 3 步：开**两个**终端，其中一个专门跑服务

⚠️ 这一步是新手最容易卡住的地方：**服务启动后会一直占着终端**，所以你需要两个终端窗口。

**终端 A（跑服务，启动后别关、别按 Ctrl+C）**：

    cd E:\my-project\offermate\server
    mvn spring-boot:run -Dspring-boot.run.profiles=bench

等它打印出 Tomcat started on port 18080 之类的字样，就是起来了。（本机 8080 被别的项目占着，所以我们用 18080）

**终端 B（跑压测命令，后面所有命令都在这里敲）**：

    cd E:\my-project\offermate\bench

> 为什么要加 -Dspring-boot.run.profiles=bench ？
> 因为两个压测专用接口只在 bench 配置下才会注册，平时启动是看不到的（生产安全）。

---

## 第 4 步：批量造 500 个测试账号

在**终端 B** 里：

    java -Dstdout.encoding=UTF-8 Bench.java --prepare 500

几十秒后应该看到：

    prepared 500 accounts (failed: 0) -> tokens.txt

**这一步干了什么**：自动注册 500 个账号（手机号 13900000001 起）、逐个登录、把登录态存到 tokens.txt。

为什么要 500 个账号？因为**不能拿一个账号去压**——会被限流和唯一约束挡住，测出来的数字是假的。

---

## 第 5 步：压**同步版**（对照组）

    java -Dstdout.encoding=UTF-8 Bench.java --path /api/bench/apply-sync --concurrency 500 --requests 5000

**这个接口模拟的是「重构前」的写法**：落库 → 等三方解析（默认 800 毫秒）→ 等写站内信 → 才返回。

跑完会打印一张表，把 P99 和 P95 记下来：

    latency (ms) : P50 ... P95 ... P99 ... max ... avg ...

---

## 第 6 步：压**异步版**（现在的写法）

    java -Dstdout.encoding=UTF-8 Bench.java --path /api/bench/apply-async --concurrency 500 --requests 5000

同样记下 P99 / P95。

**两个数字的差距，就是你简历上那条 bullet 的来源。**

---

## 第 7 步：填进简历

模板（把 X 换成你测出来的数）：

> 引入 RocketMQ 将简历解析、JD 匹配与通知推送全链路异步化，投递主链路只做校验、落库与消息投递；
> 引入 RocketMQ 将简历解析、JD 匹配与通知推送全链路异步化，投递主链路只保留校验、落库与消息投递；
> 接口单次响应 841ms → 21ms（受控对照接口，剥离限流/幂等/分布式锁），50 并发下吞吐提升约 5.5 倍（50 → 275 req/s），P99 1.28s → 596ms（本机 Docker 实测）

面试官追问时的标准答法：

> "同一套业务我做了两个分支对比：一个把解析、算分、通知同步做完，一个只落库加发消息。用自己写的压测工具打 50 并发，每轮压测前清空数据表，只取成功率 100% 的那轮，对比 P95 和 P99。环境是我本机 Docker 起的 MySQL、Redis、RocketMQ，压测客户端和服务同一台机器，所以只能说明趋势，不代表线上。"

## 常见报错对照表

| 报错 | 原因 | 怎么办 |
| --- | --- | --- |
| docker 不是内部或外部命令 | 没装 Docker | 见下方「没有 Docker 怎么办」 |
| 端口 6379 / 9876 被占用 | 本机已经装过 Redis、RocketMQ | 先停掉本机的服务，或改 docker-compose.yml 的端口映射 |
| 连不上数据库 | Docker 里的 MySQL 端口是 **13306**（不是 3306） | 已在 docker-compose.yml 和 application.yml 里统一改成 13306，避开你本机的 MySQL |
| 启动服务报 Redis 连不上 | Redis 容器没起来 | docker ps 看容器状态；再 docker compose restart redis |
| 压测返回 401 | 登录态过期（有效期 24 小时） | 重新跑一次 --prepare 500 |
| 压测大量 429 | 说明压到了真实业务接口（带限流） | 确认路径是 /api/bench/... 而不是 /api/application |
| 压测大量连接失败 | 客户端或系统连接数限制 | 把 --concurrency 降到 200 再跑 |
| 服务启动就退出、日志有 OutOfMemory | 内存不够 | 关掉别的程序；或放弃这条路，改用简历的「量级写法」 |
| 数据库表不存在 | 自动建表没跑到 | 见第 2 步的手动执行命令 |

## 没有 Docker 怎么办

**选项一：装 Docker Desktop（推荐）**

1. 去 docker.com 官网下载 Docker Desktop for Windows
2. 安装时勾选 WSL2 支持，装完**重启电脑**
3. 启动 Docker Desktop，等左下角变成绿色（Engine running）
4. 回到第 0 步重新自查

提醒：Docker Desktop 比较吃内存（1~2GB），如果电脑内存只有 8GB，跑起来会比较勉强。

**选项二：不跑了，用「量级写法」写简历**

把简历那条改成不需要精确数字的版本：

> 将投递主链路重构为「校验 + 落库 + 发消息」，简历解析、匹配打分、通知推送全部改为消息队列异步处理，
> 接口不再等待任何外部调用（本地压测对比：P99 由秒级降至毫秒级）

这句话完全站得住，因为它是从原理推导出来的。面试官追问「为什么能降这么多」，你能答：
**主链路里没有任何外部调用，剩下的只有 Redis 操作和一次数据库写入。**

**唯一的红线**：不要写具体数字（比如 50ms、2.8s），除非你真跑过。
